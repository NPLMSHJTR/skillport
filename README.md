# skillport

**Write an Agent Skill once. Keep it in sync everywhere it needs to be.**

[![CI](https://github.com/NPLMSHJTR/skillport/actions/workflows/ci.yml/badge.svg)](https://github.com/NPLMSHJTR/skillport/actions/workflows/ci.yml)
![python](https://img.shields.io/badge/python-3.9%2B-blue)
![license](https://img.shields.io/badge/license-MIT-green)
![dependencies](https://img.shields.io/badge/dependencies-zero-brightgreen)

Every agent that supports skills looks for them somewhere different:

```
.codex/skills/       .claude/skills/       .agents/skills/
.cursor/skills/      .gemini/skills/       .windsurf/skills/
```

So people copy. They copy once, then edit one copy, then forget which one is real,
then stop trusting all of them. `skillport` keeps one source directory and syncs
it out, and — more importantly — tells you when a copy has drifted.

```console
$ skillport check

source: skills  (2 skills)
targets: codex, claude, agents

  sync     codex      changelog-from-tags
  sync     codex      csv-profile
  sync     claude     changelog-from-tags
  drifted  claude     csv-profile
             changed: SKILL.md
  sync     agents     changelog-from-tags
  sync     agents     csv-profile

1 drifted  → run `skillport sync`
```

## Why drift detection is the point

Copying files is a one-liner. Knowing whether the copies are still the same is
the part that has no tooling, and it is the part that matters: a stale copy is
worse than a missing one, because the agent follows it and the behaviour is wrong
in a way nobody can see.

The design follows from that:

- **Fingerprints, not byte comparison.** Each skill gets a hash over its
  normalised content: paths plus per-file hashes, with line endings and trailing
  whitespace normalised, and packaging files excluded. A Windows checkout and a
  Linux checkout of the same skill are in sync, which they are.
- **`check` never writes.** It is safe in CI and safe in a pre-commit hook.
- **`prune` requires `--yes`.** Deleting is the only operation that can lose
  work, so it never happens implicitly, and it only touches directories that
  contain a `SKILL.md`.
- **Reported paths are labelled.** `skillport list` marks which target paths are
  verified against documentation and which are community-reported. A tool that
  silently guesses where to write files is worse than one that says it is
  guessing.

## Install

```bash
pipx install git+https://github.com/NPLMSHJTR/skillport
```

Or from source, with no dependencies:

```bash
git clone https://github.com/NPLMSHJTR/skillport
cd skillport
python -m skillport check .
```

## Use

```bash
skillport list                      # targets and presets
skillport check                     # report drift, writes nothing
skillport sync                      # copy source into every target
skillport sync --dry-run            # show what would be written
skillport sync --skill my-skill     # sync one skill
skillport prune                     # preview orphans
skillport prune --yes               # remove them
```

Exit codes:

| code | meaning |
| --- | --- |
| `0` | everything in sync, or the operation succeeded |
| `1` | `check` found missing, drifted, or extra skills |
| `2` | usage error, or `prune` without `--yes` |

## Targets

| name | directory | confidence |
| --- | --- | --- |
| `codex` | `.codex/skills` | verified |
| `claude` | `.claude/skills` | reported |
| `agents` | `.agents/skills` | reported |
| `cursor` | `.cursor/skills` | reported |
| `gemini` | `.gemini/skills` | reported |
| `windsurf` | `.windsurf/skills` | reported |
| `opencode` | `.opencode/skills` | reported |

Presets: `codex`, `claude`, `common` (codex + claude + agents), `all`.

**On "reported":** `verified` means the path was checked against that agent's own
documentation or a working installation. `reported` means it is widely repeated in
the community and I have not confirmed it myself. Full notes in
[docs/compatibility.md](docs/compatibility.md). If you know one of these is wrong,
that is the most useful issue you can open.

## Layout

The source is a directory of skills, each with a `SKILL.md`:

```
your-project/
├── skills/                    ← the only place you edit
│   ├── example-review/
│   │   ├── SKILL.md
│   │   └── references/
│   │       └── severity.md
│   └── changelog/
│       └── SKILL.md
├── .codex/skills/             ← generated by `skillport sync`
├── .claude/skills/            ← generated
└── .agents/skills/            ← generated
```

The generated directories are output. Add them to `.gitignore` if you want the
source to be the only thing in version control — but consider committing them
instead: then `skillport check` in CI proves the copies match on every push, and a
reviewer can see what changed.

## In CI

```yaml
- run: skillport check
```

That is the whole thing. It fails the build when a copy drifts, which is the
moment you want to know.

If you commit the generated directories, freezing them like this is meaningful:

```yaml
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install git+https://github.com/NPLMSHJTR/skillport
      - run: skillport check
```

## What it does not do

- **It does not translate between formats.** Today the target formats are the
  same on disk (a directory with `SKILL.md`), so there is nothing to translate.
  When an agent diverges, `targets.py` is where that goes.
- **It does not resolve dependencies between skills.** Referencing one skill from
  another is undeclared everywhere; a lockfile is a different tool.
- **It does not verify a skill is any good.** Use a linter for structure and a
  reviewer for judgment.
- **It does not follow symlinks into targets.** Copies are real files, because
  symlinks break on Windows and break differently in containers.

## Status

Version 0.1.0. The CLI contract and the fingerprint format are stable.

Known limits, stated plainly:

- Fingerprints ignore `plugin.json`, `.codex-plugin`, `manifest.json` and
  similar packaging files, on the theory that they differ legitimately per
  target. If a target needs a manifest whose content encodes the skill's
  behaviour, this will under-report drift.
- `sync` replaces the whole destination directory. A hand-edit inside a target is
  destroyed, which is the intent, but it is worth knowing before the first run.
- Only directories containing `SKILL.md` are considered skills.
